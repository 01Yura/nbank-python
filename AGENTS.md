# AGENTS.md — контекст для ассистентов и разработчиков

## Назначение проекта

Это **учебный** репозиторий. Он служит площадкой для практики автоматизации: здесь собраны **API- и UI-тесты**, оформленные как примеры **разного уровня сложности и зрелости** — условно **junior**, **middle** и **senior** (по папкам/слоям или по стилю написания, в зависимости от того, как развивается структура).

Цель — показать, как одну и ту же предметную область можно покрывать тестами с разной глубиной абстракций, переиспользования и устойчивости к изменениям.

## Состояние репозитория

Проект **ещё не доведён до конца**: часть сценариев, уровней или документации может отсутствовать или меняться. Перед изменениями имеет смысл сверяться с актуальной структурой каталога `tests/` и с `pytest.ini`.

## Технологии и запуск

- **Python**, **pytest** — основной раннер тестов.
- Зависимости перечислены в `requirements.txt` (в т.ч. `requests` для API).
- Настройки pytest: `pytest.ini` (пути к тестам, шаблоны имён файлов/классов/функций, маркеры `api`, `ui`, `debug`).

Запуск всех тестов из корня репозитория:

```bash
pytest
```

Примеры выборочного запуска по маркерам (если тесты помечены):

```bash
pytest -m api
pytest -m ui
```

## Структура тестов (на момент описания)

- `tests/` — корень тестового дерева (`testpaths` в `pytest.ini`).
- Подкаталоги могут отражать тип тестов (`api`, `ui`) и/или уровень (`junior`, `middle`, `senior`) — по мере наполнения репозитория.

При добавлении новых файлов соблюдайте соглашения об именах из `pytest.ini` (`*_test.py`, `test_*.py` и т.д.).

## Прочее

- В репозитории могут быть вспомогательные материалы (например, HTTP-запросы в `requests/`, инфраструктура в `infra/`) — уточняйте по фактическим файлам в дереве проекта.
